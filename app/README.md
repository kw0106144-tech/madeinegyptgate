# The native apps: «صنع في مصر» / Made in Egypt Gate (iOS + Android)

Capacitor **8.6.2** apps that show the live site **https://madeinegyptgate.com** in the system WebView (WKWebView on iOS, Android
System WebView), so every change of the site is in the apps at once, with no app update. App id `com.madeinegyptgate.app` on both
stores. Owner's short guide (Egyptian Arabic): `OWNER-GUIDE-AR.md` section 10.

Nothing in `app/` is part of the site: `deploy-site` ignores `app/**` and the two app workflows, the app workflows have no
Cloudflare token and deploy nothing (CLAUDE.md section 4).

## Layout

| Path | What |
|---|---|
| `package.json`, `package-lock.json` | Capacitor core / CLI / android / ios 8.6.2 and the plugins: app, browser, keyboard, network, push-notifications, share, splash-screen, status-bar (exact versions) |
| `capacitor.config.json` | `server.url` = the live site, `server.allowNavigation` = `madeinegyptgate.com` + `www`, user agent marks, splash / status bar colours, plugin settings |
| `www/` | `offline.html` (shown when the site cannot load; Arabic + English, inline logo, ES5) and `index.html` (needed by Capacitor, redirects to the site) |
| `android/` | The Android Studio project (generated by `npx cap add android`, then edited: see "Native code") |
| `ios/` | The Xcode project, Swift Package Manager (no CocoaPods), generated by `npx cap add ios`, then edited |
| `tools/make_assets.py` | Icons + splash screens for every size + store graphics, from `img/logo-site.png` (Pillow) |
| `tools/ios_project.py` | The app's edits of the Xcode project (re-applies them, `--check` verifies them, `--ci-sign` is for CI) |
| `tools/check-app.mjs` | `npm run check`: offline checks of all of the above (CI runs it first) |
| `store/` | Store listing texts (fastlane layout, Arabic + English) and graphics: `store/README.md` |
| `well-known/` | Templates of the two app-links files the SITE serves (Android: generated by the site build since 2026-11-20; iOS: later): `well-known/README.md` |

## What the app does

| Topic | Behaviour | Where |
|---|---|---|
| Content | The live site, loaded from `https://madeinegyptgate.com` (`server.url`). The site's own pages, language switch, sign-in (token in the WebView's storage), Janna / Bassem, forms, uploads | `capacitor.config.json` |
| Telling the site it is in the app | The user agent ends with `MIGApp/1.0 (android)` or `MIGApp/1.0 (ios)` | `android.appendUserAgent`, `ios.appendUserAgent` |
| Other hosts | Only `madeinegyptgate.com` and `www.madeinegyptgate.com` load in the app; every other link opens in the phone's browser or its own app (WhatsApp, mail, phone, maps, payment pages). On iOS a link with `target=_blank` opens in Safari even for the site (Capacitor's `createWebViewWith`) | `server.allowNavigation`, Capacitor |
| Android back button | One step back in the site's history (it skips the offline page and the page that failed); on the first page «الخروج من التطبيق؟» / "Exit the app?" | `MainActivity.java`; `plugins.App.disableBackButtonHandler` |
| Offline / error page | `www/offline.html` (Arabic + English, brand colours), only when the site really cannot be reached (no network, DNS, timeout, TLS). It retries the page that failed by itself when the connection returns. The site's own 404 / 410 pages and Cloudflare challenges stay on screen, a cancelled navigation does nothing: that is why there is no `server.errorPath` (Capacitor would show it for every HTTP error on Android and for cancelled loads on iOS) | `MigWebViewClient.java`, `MainViewController.swift` |
| Live calls (Janna / Bassem) | Microphone (and camera if a page asks) through WebRTC `getUserMedia` inside the WebView. Android: `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS`, `CAMERA`; Capacitor's `BridgeWebChromeClient.onPermissionRequest` asks Android, then grants the page (verified in the 8.6.2 source; the app allows it only for the site's own origin). iOS: `NSMicrophoneUsageDescription` / `NSCameraUsageDescription` (Arabic + English), Capacitor grants WebKit's media-capture request, inline playback without a tap (`allowsInlineMediaPlayback`, `mediaTypesRequiringUserActionForPlayback = []`, set by Capacitor) | `AndroidManifest.xml`, `MigChromeClient.java`, `Info.plist`, `InfoPlist.strings` |
| Uploads (`<input type=file>`) | The system file picker (documents, photos) or the camera when the input asks for capture. Android: Capacitor's `onShowFileChooser` + `<queries>` for the camera app; iOS: WKWebView's own picker (`NSPhotoLibraryUsageDescription`, `NSCameraUsageDescription`) | Capacitor, `AndroidManifest.xml` |
| Files the site hands out | Android: an https file link opens in the browser (which downloads it); a file the page makes itself (`blob:` / `data:`, e.g. the .ics of «أضف إلى التقويم») opens in the matching app or the share sheet. iOS: downloads go to the share sheet | `MigDownloads.java`, `MainViewController.swift` |
| Full-screen video | Works on Android (Capacitor closes it at once by default) and iOS (WebKit) | `MigChromeClient.java` |
| Status bar, splash | Brand red `#8E0B20` (the site's top bar and footer) with light icons; the splash is the round badge on red. Android (edge to edge from Android 15): `MainActivity.keepWebViewBetweenBars` pads the WebView by the bars on every page, so the window's red shows behind them. Capacitor's own handling is off (`plugins.SystemBars.insetsHandling: "disable"`): with WebView 140+ it puts every page with `viewport-fit=cover` under the bars, and most of the site's own pages have it (`/`, `/market/`, `/advisor/`, `/register/` …; the generated hubs such as `/factories/` do not), where the site paints the strip white (`body::before`, `var(--surface)`): the white icons would vanish. iOS: `contentInset: always` keeps the page below the status bar (the page sees `env(safe-area-inset-*)` = 0); not checked on a device yet | `MainActivity.java`, `styles.xml`, `capacitor.config.json` |
| App name | «صنع في مصر» on Arabic phones, "Made in Egypt Gate" on all others | `values-ar/strings.xml`, `values/strings.xml`, `InfoPlist.strings` |
| Deep links | Prepared: Android App Links (`autoVerify`, host `madeinegyptgate.com`) and iOS Universal Links (`applinks:madeinegyptgate.com`). A tapped link opens that page in the app, cold start or running. Android: the site serves `/.well-known/assetlinks.json` (the release key of the APK on `/app/`, CLAUDE.md 5.7); iOS starts once the site serves `apple-app-site-association` (`well-known/`) | `AndroidManifest.xml`, `App.entitlements`, `MainActivity.java`, `MainViewController.swift` |
| Push notifications | Wired, **off**: plugin installed, Android `POST_NOTIFICATIONS` declared, Firebase applied only when `google-services.json` exists, iOS token forwarding in `AppDelegate.swift`. Nothing asks for permission. See "Push" | |

## Build here

Requirements: Node 22+, JDK 21 (Android Gradle Plugin 8.13, Gradle 8.14.3 wrapper with a pinned checksum), Android SDK with
`platforms;android-36` and `build-tools;35.0.0`; for iOS a Mac with Xcode 16+ (Capacitor 8.6 is tested with Xcode 26).

```bash
cd app
npm ci
npm run check                       # offline checks (add ACORN_DIR=<dir with node_modules/acorn> for the ES5 check)
npx cap sync                        # copies www/ + capacitor.config.json into both projects, updates the plugins
cd android && ./gradlew assembleDebug testDebugUnitTest   # → android/app/build/outputs/apk/debug/app-debug.apk
```

iOS (on a Mac): `npx cap sync ios`, then open `ios/App/App.xcodeproj` (no workspace, no `pod install`: Swift Package Manager
resolves Capacitor and the plugins from `node_modules` and GitHub), or the simulator build of `.github/workflows/app-ios.yml`.

After changing the logo: `python3 tools/make_assets.py [--logo master.png] [--font Cairo-Bold.ttf]` and commit what it rewrote.
The current master `img/logo-site.png` is only about 200 px wide, so the 1024 px icons are upscaled: a vector or ≥ 1024 px master
of the badge would make them sharp (nothing else changes). After a fresh `npx cap add ios`: `python3 tools/ios_project.py`.

## CI (GitHub Actions)

| Workflow | Runs on | Always | When the secrets are set |
|---|---|---|---|
| `app-android.yml` | push to `main` touching `app/**`, «Run workflow» | `npm run check`, debug APK, unit tests → artifact `android-debug-apk` (14 days), summary with SHA-256 and signing certificate | signed release `.aab` (for Google Play) + `.apk` → artifact `android-release` (30 days). `versionCode` = the run number, `versionName` = `package.json` version |
| `app-ios.yml` | same | `npm run check`, simulator build with the newest Xcode on `macos-latest` (proves it compiles) | signed App Store archive → IPA (artifact `ios-ipa`) → TestFlight upload. Build number = the run number |

`permissions: contents: read`, no Cloudflare token, nothing is published to a store automatically except the TestFlight upload
(TestFlight builds are visible only to the testers you add).

### Android signing (secrets)

1. Make the **upload key** once (keep the file and both passwords safe, outside the repository; with Play App Signing a lost upload
   key can be reset by Google support, the app signing key is held by Google):
   `keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 9125`
2. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   - `ANDROID_KEYSTORE_BASE64` = `base64 -w0 upload.jks` (macOS: `base64 -i upload.jks`)
   - `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`upload` above), `ANDROID_KEY_PASSWORD`
3. Google Play Console → create the app «منصة صنع في مصر» (default language Arabic, add English), upload the first `.aab` by hand
   (Test and release → Internal testing), accept **Play App Signing** — with the release key of the APK already offered on `/app/`
   if the people who installed it from the site should get Play's updates (Android updates only with the same key). Then App
   integrity → App signing → add the **app signing key SHA-256** to `seo/config.json` `"app"` `android_cert_sha256` (the site
   serves it in `/.well-known/assetlinks.json`).

### iOS signing (secrets)

In Apple Developer (Certificates, Identifiers & Profiles) and App Store Connect:
1. Identifier: App ID `com.madeinegyptgate.app`, capability **Associated Domains** (later **Push Notifications** too).
2. Certificate: **Apple Distribution**; export it from Keychain Access as `.p12` with a password.
3. Profile: **App Store Connect** distribution profile for that App ID and certificate (make it again after adding a capability).
4. App Store Connect → Apps → New App: platform iOS, name «منصة صنع في مصر», primary language Arabic, bundle ID above, SKU of your choice.
5. App Store Connect → Users and Access → Integrations → **App Store Connect API** → a key with the App Manager role: Key ID,
   Issuer ID, the `.p8` file (downloadable once).
6. GitHub secrets: `APPLE_TEAM_ID` (Membership → Team ID), `APPLE_DIST_CERT_P12_BASE64` (`base64 -i dist.p12`),
   `APPLE_DIST_CERT_PASSWORD`, `APPLE_PROVISIONING_PROFILE_BASE64` (`base64 -i profile.mobileprovision`), `APPSTORE_API_KEY_ID`,
   `APPSTORE_API_ISSUER_ID`, `APPSTORE_API_KEY_P8` (the text of the `.p8`, including the BEGIN / END lines).

The signed iOS build sets manual signing on the App target's Release configuration inside the CI checkout only
(`tools/ios_project.py --ci-sign`), because signing settings on the xcodebuild command line would also hit the Swift packages.

## Push notifications (off: what turning them on needs)

| Piece | Needed | Who |
|---|---|---|
| Android | A Firebase project with the Android app `com.madeinegyptgate.app` → `google-services.json` at `app/android/app/google-services.json` (git-ignored: in CI add it as a secret and write it before the build). The Gradle file already applies the Google Services plugin when the file exists | owner creates the project, developer wires the secret |
| iOS | Apple Developer → Keys → an **APNs key** (`.p8`, Key ID, Team ID); App ID capability **Push Notifications**; `aps-environment` = `production` in `App.entitlements`; a new provisioning profile | owner + developer |
| Sending | A Worker endpoint family (for example `/api/push/*`, routes in `worker/wrangler.toml`) that stores device tokens per signed-in member (new D1 table, migration) and sends: FCM HTTP v1 (Worker secret with the Firebase service account) and APNs (Worker secrets with the `.p8`, Key ID, Team ID) | developer |
| Asking the user | The site, when `window.Capacitor && Capacitor.isNativePlatform()`, asks at a useful moment (for example after sign-in, «تنبيهات الطلبات الجديدة»), calls `Capacitor.Plugins.PushNotifications.requestPermissions()` / `register()` and sends the token to the Worker (the Capacitor bridge is injected only on `https://madeinegyptgate.com`, not on `www`) | developer, owner approves the wording |

## Before submitting to the stores (owner decisions, nothing applied)

1. **Privacy policy** (`/legal/#privacy`) does not mention the app or the voice of the live calls yet. Proposed addition, to be
   approved word for word by the owner (CLAUDE.md 2.7):
   - «تطبيق المنصة على الهاتف يعرض موقع المنصة نفسه وتنطبق عليه هذه السياسة. عند بدء مكالمة مباشرة مع جنة أو باسم يطلب التطبيق إذن الميكروفون، ويُرسل الصوت أثناء المكالمة إلى مزوّد خدمة المحادثة المرئية (Anam) لمعالجته وتوليد الرد، ولا يُستخدم الميكروفون خارج المكالمة. وتُستخدم الكاميرا ومكتبة الصور فقط عندما يختار المستخدم رفع صورة أو مستند.»
   - "The platform's mobile app shows the platform's website, and this policy applies to it. When you start a live call with Janna or Bassem, the app asks for microphone permission; during the call your voice is sent to the video-conversation provider (Anam) to be processed and answered, and the microphone is not used outside the call. The camera and the photo library are used only when you choose to upload a picture or document."
2. **Account deletion**: Apple (5.1.1 v) requires members to be able to start deleting their account inside the app; Google Play
   asks for an account-deletion link in the Data safety form. The site has no member-side deletion request today.
3. **Paid plans on iPhone**: Apple usually requires In-App Purchase for digital subscriptions bought inside an app (3.1.1). The
   safe path: the site hides plan checkout when the user agent contains `MIGApp/1.0 (ios)` (members pay on the website). Google
   Play has a similar payments policy; the payment pages already open outside the app (other hosts).
4. **Minimum functionality**: Apple rejects apps that are "just a website" (4.2). The app has native behaviour (Universal Links,
   offline page, files, full-screen video, back navigation on Android) and turning push notifications on before the first iOS
   submission makes the case much stronger.
5. **Store forms**: content rating questionnaire; Google "Data safety" and Apple "App Privacy" (data the site collects: account and
   company details, messages / requests, voice during live calls, usage); screenshots (phone 1080×1920+ for Play; iPhone 6.9″ or
   6.5″ and, because iPad is supported, iPad 13″ for the App Store): take them from the test APK / TestFlight build.

## Upgrading Capacitor

`npm i @capacitor/core@X @capacitor/cli@X @capacitor/android@X @capacitor/ios@X` (+ plugins), `npx cap sync`, build both. Then
re-check what the native code relies on: `BridgeWebViewClient.onReceivedError`, `BridgeWebChromeClient` (permission grants, file
chooser, `onShowCustomView`), `Bridge.setWebViewClient`, that `SystemBars` with `insetsHandling: "disable"` still sets no window
insets listener (MainActivity owns it), and on iOS the `WebViewDelegationHandler` navigation methods that
`MIGWebDelegate` forwards (listed in `MainViewController.swift`).
