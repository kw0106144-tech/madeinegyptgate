# The native apps: «صنع في مصر» / Made in Egypt Gate (iOS + Android)

Capacitor **8.6.2** apps that show the live site **https://madeinegyptgate.com** in the system WebView (WKWebView on iOS, Android
System WebView), so every change of the site is in the apps at once, with no app update. App id `com.madeinegyptgate.app` on both
stores. Owner's short guide (Egyptian Arabic): `OWNER-GUIDE-AR.md` section 10.

Nothing in `app/` is part of the site: `deploy-site` ignores `app/**` and the two app workflows, the app workflows have no
Cloudflare token and deploy nothing (CLAUDE.md section 4).

## Layout

| Path | What |
|---|---|
| `package.json`, `package-lock.json` | Capacitor core / CLI / android / ios 8.6.2 and the plugins: app, browser, keyboard, network, push-notifications, share, splash-screen, status-bar (exact versions; the iPhone app leaves the keyboard plugin out: `ios.includePlugins`) |

## Build here

Requirements: Node 22+, JDK 21 (Android Gradle Plugin 8.13, Gradle 8.14.3 wrapper with a pinned checksum), Android SDK with
`platforms;android-36` and `build-tools;35.0.0`; for iOS a Mac with Xcode 16+ (Capacitor 8.6 is tested with Xcode 26).

```bash
cd app
npm ci
npm run check                       # offline checks (add ACORN_DIR=<dir with node_modules/acorn> for the ES5 check)
npx cap sync                        # copies www/ + capacitor.config.json into both projects, updates the plugins
cd android && ./gradlew assembleDebug testDebugUnitTest lintDebug   # → android/app/build/outputs/apk/debug/app-debug.apk
```

The JVM tests (`MigLogicTest`: links, Back, new windows, restore, App Links, the microphone queue, file names, the chooser) also
write the scripts the Android app puts into the site's pages to `android/app/build/mig-page-scripts/`. They run in visitors'
WebViews, so they are ES5 like the site (CLAUDE.md 2.1): `acorn --ecma5 android/app/build/mig-page-scripts/*.js`. What they do
in a real Chrome (pull to reload, print, page-made files, "is a call open?"): `node tools/page-scripts.test.mjs` (optional; needs
`playwright-core` and Chrome, see its header).

iOS (on a Mac): `npx cap sync ios`, then open `ios/App/App.xcodeproj` (no workspace, no `pod install`: Swift Package Manager
resolves Capacitor and the plugins from `node_modules` and GitHub), or the simulator build of `.github/workflows/app-ios.yml`.

After changing the logo: `python3 tools/make_assets.py [--logo master.png] [--font Cairo-Bold.ttf]` and commit what it rewrote.
The current master `img/logo-site.png` is only about 200 px wide, so the 1024 px icons are upscaled: a vector or ≥ 1024 px master
of the badge would make them sharp (nothing else changes). After a fresh `npx cap add ios`: `python3 tools/ios_project.py`.

## CI (GitHub Actions)

| Workflow | Runs on | Always | When the secrets are set |
|---|---|---|---|
| `app-android.yml` | push to `main` touching `app/**`, «Run workflow» | `npm run check`, debug APK, unit tests → artifact `android-debug-apk` (14 days), summary with SHA-256 and signing certificate | signed release `.aab` (for Google Play) + `.apk` → artifact `android-release` (30 days). `versionCode` = the run number, `versionName` = `package.json` version |
| `app-ios.yml` | same | `npm run check`, simulator build with the newest Xcode on `macos-latest` (proves it compiles) | signed App Store archive → IPA (artifact `ios-ipa`) → TestFlight upload. Build number = the run number |

`permissions: contents: read`, no Cloudflare token, nothing is published to a store automatically except the TestFlight upload
(TestFlight builds are visible only to the testers you add).

### Android signing (secrets)

1. Make the **upload key** once (keep the file and both passwords safe, outside the repository; with Play App Signing a lost upload
   key can be reset by Google support, the app signing key is held by Google):
   `keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 4096 -validity 9125`
2. GitHub → Settings → Secrets and variables → Actions → New repository secret:
   - `ANDROID_KEYSTORE_BASE64` = `base64 -w0 upload.jks` (macOS: `base64 -i upload.jks`)
   - `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` (`upload` above), `ANDROID_KEY_PASSWORD`
3. Google Play Console → create the app «منصة صنع في مصر» (default language Arabic, add English), upload the first `.aab` by hand
   (Test and release → Internal testing), accept **Play App Signing** — with the release key of the APK already offered on `/app/`
   if the people who installed it from the site should get Play's updates (Android updates only with the same key). Then App
   integrity → App signing → add the **app signing key SHA-256** to `seo/config.json` `"app"` `android_cert_sha256` (the site
   serves it in `/.well-known/assetlinks.json`).

### iOS signing (secrets)

In Apple Developer (Certificates, Identifiers & Profiles) and App Store Connect:
1. Identifier: App ID `com.madeinegyptgate.app`, capability **Associated Domains** (later **Push Notifications** too).
2. Certificate: **Apple Distribution**; export it from Keychain Access as `.p12` with a password.
3. Profile: **App Store Connect** distribution profile for that App ID and certificate (make it again after adding a capability).
4. App Store Connect → Apps → New App: platform iOS, name «منصة صنع في مصر», primary language Arabic, bundle ID above, SKU of your choice.
5. App Store Connect → Users and Access → Integrations → **App Store Connect API** → a key with the App Manager role: Key ID,
   Issuer ID, the `.p8` file (downloadable once).
6. GitHub secrets: `APPLE_TEAM_ID` (Membership → Team ID), `APPLE_DIST_CERT_P12_BASE64` (`base64 -i dist.p12`),
   `APPLE_DIST_CERT_PASSWORD`, `APPLE_PROVISIONING_PROFILE_BASE64` (`base64 -i profile.mobileprovision`), `APPSTORE_API_KEY_ID`,
   `APPSTORE_API_ISSUER_ID`, `APPSTORE_API_KEY_P8` (the text of the `.p8`, including the BEGIN / END lines).

The signed iOS build sets manual signing on the App target's Release configuration inside the CI checkout only
(`tools/ios_project.py --ci-sign`), because signing settings on the xcodebuild command line would also hit the Swift packages.

## Before submitting to the stores (owner decisions, 2026-11-20)

## Upgrading Capacitor

`npm i @capacitor/core@X @capacitor/cli@X @capacitor/android@X @capacitor/ios@X` (+ plugins), `npx cap sync`, build both. Then
re-check what the native code relies on: `BridgeWebViewClient.onReceivedError` / `onPageFinished` / `onRenderProcessGone`,
`BridgeWebChromeClient` (permission grants, file chooser, `onShowCustomView`; its constructor registers result launchers, so
`MigChromeClient` must still be built in `MainActivity.onCreate`), `Bridge.setWebViewClient`, `Bridge.launchIntent` (other hosts of
the main page), that Capacitor's document-start bridge script stays limited to `https://madeinegyptgate.com` and is never added to
page windows, that `CapacitorCookies` still removes session cookies only at start / destroy (`MainActivity.restoreLegacySession`),
that Capacitor's own `res/layout/capacitor_bridge_layout_main.xml` is still one `CapacitorWebView` with the id `webview` (the
app's file of the same name overrides it; `npm run check` compares them), that `SystemBars` with `insetsHandling: "disable"`
still sets no window insets listener (MainActivity owns it), and on iOS the `WebViewDelegationHandler` navigation methods that
`MIGWebDelegate` forwards and the UI-delegate methods that `MIGUIDelegate` forwards (media capture, device orientation, the
`CapacitorCookies` prompts; listed in `MainViewController.swift`). A new plugin must also be added to `ios.includePlugins`
(`npm run check` says so), or `npx cap sync ios` leaves it out of the iPhone app.
